# Security reporting

This project is a design and contract baseline. No appliance-control application has been released. No maintainer security email or verified private vulnerability-reporting endpoint is configured by this package.

Do not post credentials, live device identifiers, full packet captures, or sensitive exploit details in public issues. Contact the repository owner through a verified private channel first. Before release, the owner must configure and publish a real private reporting procedure; do not invent a security address or URL.

Useful reports identify the affected component, version/commit, minimal redacted reproduction, expected/actual outcome, and whether duplicate physical actions, permission bypass, credential leakage, or background work are involved. Do not include passwords when a reproduction does not require them.

No response SLA or supported release range is promised. Define support versions, patch policy, and coordinated disclosure before publishing an application. See [Security and privacy](docs/security-and-privacy.md).
